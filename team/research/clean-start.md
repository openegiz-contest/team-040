# Проверка запуска из чистой копии — 15 октября 2026

## Окружение и изоляция

Проверена база `ec1d32d` из `git archive HEAD`, без локального `.env`, игнорируемых
файлов и данных рабочего стенда. Исправление ожидания данных команды проверено
поверх этой базы: Makefile, scripts/compose-team-ready.sh и
team/gateway/readiness.py. Файлы визуала Claude не менялись.

Ubuntu 24.04 amd64, Python 3.12.3, Docker Engine 29.9.1, Compose 5.6.0.
Окружение — отдельный привилегированный контейнер `team040-cleancheck-20261015`
со своим Docker daemon, socket, сетью, образами и томами. Socket рабочего Docker
в него не монтировался; исходники переданы архивом. Лимит памяти — 8 ГиБ;
первоначальный лимит CPU — 4, заключительные проверки — 8.

Установка Docker — через [официальный apt-репозиторий](https://docs.docker.com/engine/install/ubuntu/).
До первого запуска приложения подтверждены: Images=0, Containers=0, отсутствие
томов и deploy/compose/.env. Порты, параметры модели, пароли и конфигурация
приложения вручную не задавались. Зависимости Python устанавливались Dockerfile;
дополнительный API собирался из закреплённого Git-коммита, плагины Grafana — из
файлов репозитория. Готовые образы рабочего стенда не копировались.

Это чистая Ubuntu userspace и отдельные данные Docker, **не отдельная VM с
идентичным жюри ядром**. Ядро общее с Docker Desktop, хранилище теста — VFS.
Время запуска здесь нельзя считать обещанием производительности другой машины.

## Найденные проблемы

1. Две ранние попытки остановились из-за вложенной среды: overlayfs не смог
   распаковать whiteout, затем cgroup не применил ограничения памяти. Для
   тестового Docker выбран VFS и включены вложенные контроллеры cgroup по
   [сценарию Moby](https://github.com/moby/moby/blob/master/hack/dind). В конфигурацию
   проекта эти настройки не добавлялись; на машине жюри DinD не требуется.
   После исправления инфраструктуры для холодной попытки создан ещё один
   пустой data-root Docker, без образов и томов.
2. При 4 CPU `make up` завершился успешно за **526 с (8 мин 46 с)**, но первый
   smoke не уложился в ожидание MQTT → Ditto → InfluxDB, а браузер не дождался
   готовых данных за 25 с. Контейнеры healthy не означали готовность двойника.
   После повышения лимита до 8 CPU и прогрева оба теста прошли. Это не отдельный
   сравнительный тест CPU: влияние прогрева и вложенного хранилища не исключено.
3. В Makefile добавлена проверка пути команды через прокси: снимок свежий,
   состав сцены соответствует manifest, все объекты относятся к одному тику
   и прогону, номер публикации растёт в трёх последовательных чтениях.
   Проверка имеет ограниченное ожидание и не выдаёт пароли. При неготовности
   `make up` завершается ошибкой, а не печатает успешное завершение.

## Воспроизведение на отдельной Ubuntu

Установить Docker с Compose и разрешить текущему пользователю работать с Docker
по документации платформы; открыть чистую копию репозитория. Затем:

```bash
sudo apt update && sudo apt install -y git make curl
make up
make smoke
python3 -m team.smoke
make down
make up
python3 -m team.restart_smoke
```

Python 3 требуется только для дополнительных тестов на хосте, симулятор работает
в контейнере. Основной UI — http://127.0.0.1:8088. Для подготовки к сдаче нужны
также финальная 3D-версия Claude и отдельная проверка на целевой VM; эта проверка
не утверждает, что будущие изменения интерфейса уже проверены.

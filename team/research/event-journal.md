# Журнал событий: контракт для интерфейса

14 октября 2026. Добавление совместимо с contract_version=1. Визуальные файлы
Claude не изменялись. Источник — `journal.features.events.properties.value`,
также внутри согласованного `shift.scene`.

Сохраняются поля `seq`, `run`, `tick`, `sim_time_s`, `code`, `subject`, `arg`,
`command_id`. Необязательное `details` содержит структурированное доказательство.
У новых кодов `arg` — готовая русская поясняющая строка, её можно вывести как
обычный текст. Текущий UI выводит неизвестный код и arg без потери содержания.
`hazard.transition` — отдельный новый код: существующий `hazard.changed` в UI
ожидает в arg только enum, поэтому его формат не переопределён.

| Код | Когда | details |
|---|---|---|
| sensor.state_changed | Изменились связь или качество датчика | before/after, measured_at_sim_s, age_s, causes |
| hazard.transition | Изменились опасность, качество данных или запрет входа участка | before/after, reason_sensor, reason_code, значение/порог/единица при наличии, последнее известное состояние, causes |
| work.changed | Остановка или возобновление участка | before/after, causes |
| withdrawal.changed | Изменение состояния вывода участка | before/after, causes |
| route.changed | Изменился путь/выход, исчез или появился маршрут | before/after: egress_status, egress_reason, exit, ориентированный path; causes |
| worker.state_changed | Человек начал движение или ожидание | before/after, causes |
| worker.exited | Человек достиг выхода | before/after, causes; выход указан в arg |
| decision.opened | Открыта или пересчитана точка сравнения | decision_id, comparison_key, causes |
| decision.selected | Выбран вариант фактического исполнения | decision_id, option |
| run.finished | Прогон завершён горизонтом или прерван reset | Метрики; причина завершения в arg |

`causes` — действующие ограничения модели на момент события, а не доказанная
физическая причина обрушения. После открытия прохода список может стать пустым;
причина отмены видна в предшествующем condition.cancelled и command_id.
Пороговые события явно называют порог условным.

Команда и вызванные ею переходы имеют одинаковый command_id. Отложенные изменения
при дальнейших тиках (устаревание, достижение выхода) не присваиваются последней
команде автоматически. Повторная доставка той же команды не повторяет события.
У command.applied arg теперь содержит тип команды, как ожидает текущий UI;
details.reason сохраняет none/already_in_state.

Порядок при обработке условия: condition → датчик → участок → маршруты →
точка решения → подтверждение команды. Время — модельное. `seq` возрастает и
после reset. Хранятся последние 50 событий вместе с checkpoint; это не полный
долговременный аудит. Скалярный экспорт InfluxDB не сохраняет массив событий.

Обычное сокращение направленного пути по мере движения не создаёт route.changed.
Разворот, выбор другого выхода и потеря пути создают событие. Выход фиксируется
один раз на человека. Прогнозные копии не пишут события в фактический журнал.
Heartbeat и обновление метаданных сами по себе событий не создают.

При обновлении 0.1 → 0.2 старый незавершённый прогон архивируется как reset,
последовательности, ledger и история сохраняются, новый прогон использует 8 людей
и 2 ПДМ. Событие model.migrated содержит from_version, to_version, previous_run.
Миграция сохраняется атомарно до публикации, повторный старт её не повторяет.

## Дополнение от 16 октября: ПДМ

| Код | Когда | details |
|---|---|---|
| equipment.state_changed | Изменились state / hold_reason | before/after, at_working, offset_m, causes |
| equipment.hazard_changed | Изменился location_hazard машины | before/after, working, zone, causes |
| equipment.conflict | Началась встреча с идущим/ожидающим человеком впереди | worker, working, gap_m, machine_offset_m, worker_offset_m, causes |
| model.migrated | Однократный переход 0.1 → 0.2 | from_version, to_version, previous_run |

Фазы обычного цикла не создают событий. Выход оператора из ПДМ создаёт
worker.state_changed даже при неизменном status: before/after включают aboard.
Эпизод встречи считается один раз до прекращения сближения; задержка учитывается
отдельно каждую секунду. Событие встречи отмечает начало интервала tick→tick+1,
gap_m использует позиции людей после их шага этого интервала (люди идут первыми).
Прогнозные копии не добавляют ни один из этих кодов в фактический журнал.

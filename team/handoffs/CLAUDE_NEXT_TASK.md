# Второе задание Claude: реализовать интерфейс по согласованному контракту

Первый результат DESIGN.md принят как основа. Codex проверил его и зафиксировал решения в team/CONTRACT.md. Сначала прочитай этот файл целиком; при расхождении он уточняет DESIGN.md. Повторный выбор замысла и ещё один самостоятельный проект контракта не нужны.

## Объём

Реализуй локальный интерфейс в team/ui/public/ на обычных ES-модулях, CSS и SVG. Тестовые инструменты, данные и README помещай в team/ui/. Изменения за пределами team/ui/ предложи в отчёте: интеграционный прокси, Docker overlay, симуляция и публикация — зона Codex.

Нужны основной экран диспетчера, пространственная схема из атрибутов платформы, список объектов, карточка, легенда трёх осей, условия сценария, действия диспетчера, журнал и состояния недоступности. Панель вариантов показывает опубликованные моделью числа или явное отсутствие прогноза. Архив различает завершённые и прерванные прогоны.

Приложение должно читать только /ditto/... своего origin. Статика поставляется целиком, без CDN и сетевых шрифтов. Пути и форма данных зафиксированы в CONTRACT.md. Боевой код не содержит встроенную шахту, генератор телеметрии или подмену ответа платформы.

Для автономной разработки создай тестовый HTTP-сервер на стандартной библиотеке Python и явно помеченные контрактные fixtures. Сервер имитирует только используемые GET/POST, возвращает HTTP Date и метаданные Ditto; это не реализация симулятора. Формат scene — массив состояний внутри одного shift, а атрибуты приходят по manifest. Документируй, что fixture-числа придуманы для тестов и не являются измерениями стенда.

## Существенные изменения к исходному DESIGN.md

- Согласованная scene в shift вместо сборки живого кадра из независимых объектов.
- Native JSON-массивы, без строк через запятую; namespace team040.mine.
- publication_seq как heartbeat: пауза времени модели не является зависанием.
- При HTTP-сбое экран сразу прекращает движение; отдельный монотонный таймер следит за устареванием даже во время fetch.
- Тайм-аут POST означает неизвестный результат доставки. Повтор идёт с тем же command_id и телом.
- Последняя известная опасность не исчезает после потери датчика.
- Число людей в зоне и человеко-секунды показаны раздельно; last_out_s отсутствует, если все люди не вышли.
- Полный reset не является успешно завершённым выводом. Новый прогон содержит подтверждение команды reset с old run и new_run.
- Сравниваются только результаты с одним comparison_key. Observe, stop_withdraw_zone, withdraw_all — три варианта первой версии.

## Проверка

Проверь как минимум: обычный кадр; обход; отсутствие пути; потерянный датчик после danger; невалидный/неполный снимок; несовпадение topology_version; пауза с живым heartbeat; отвечающий сервер с застывшим publication_seq; pending/rejected/timeout команды; повтор с тем же id; reset; неполный вывод без last_out_s; отсутствие прогноза; несколько пакетов manifest с переставленным порядком объектов.

Используй осмысленные автоматические проверки поведения и реальные снимки экрана на 1280×720 и 1920×1080. Если браузерная проверка недоступна, сообщи это явно, не подменяй её проверкой синтаксиса. Бюджеты DESIGN.md — цели; измеренные результаты укажи отдельно. Проверь управление основными кнопками с клавиатуры и читаемость состояний без цвета.

Запуск и фикстуры опиши в team/ui/README.md. Итог сохрани локальным коммитом в своей ветке; сообщи SHA, изменённые файлы, команды проверок, что проверено только на имитаторе и ограничения. В GitHub ничего не публикуй, в main не объединяй. Изменения контракта предложи отдельным перечнем с конкретной причиной.

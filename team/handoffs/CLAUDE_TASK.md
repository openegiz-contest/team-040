# Первое задание для Claude Code

Ты работаешь вместе с командой и Codex над team-040 для конкурса «Цифровой рудник на OpenEgiz». Дедлайн — 25 октября 2026 года, 23:59 по Астане. Это задание для помощника команды, не для конкурсного жюри.

## Прочитай контекст

1. AGENTS.md и CLAUDE.md.
2. SUBMISSION.md: раздел Concept уже содержит выбор команды. Не предлагай заново выбрать предприятие и пользователя.
3. team/PLAN.md.
4. team/research/safety-sources.md.
5. OPENEGIZ.ru.md и examples/mine/README.ru.md — для понимания платформы. Неизменённый пример рудника не является нашим решением.

Команда выбрала подземную рудную шахту, например медную. Пользователь — диспетчер смены. Двойник должен помогать сравнивать остановку работ и вывод персонала с учётом устойчивости выработок и доступности выходов. Данные синтетические с открыто обоснованными параметрами. Отсутствие аналогов в Казахстане не доказано.

## Первый результат

Сначала проведи независимую проверку замысла и спроектируй интерфейс диспетчера. Сохрани результат в team/ui/DESIGN.md в своей ветке.

В документе нужны:

- До пяти существенных пробелов или противоречий текущего плана, с указанием файлов и практических последствий.
- Основной экран: пространственная схема шахты, люди, участки работ, состояние датчиков, выходы и текущий сценарий. Укажи иерархию элементов и действия диспетчера.
- Подробный пользовательский путь для перекрытия прохода: до события, после события, выбор действия, результат, отмена условия и полный сброс.
- Состояния интерфейса при отсутствии маршрута, потере датчика, устаревших данных, недоступности Ditto и ещё не выполненной команде.
- Предложение по данным, которые UI должен получать от платформы: поля, единицы и пример ответа. Это предложение контракта, а не уже реализованный API.
- Критерии проверки интерфейса на программном рендеринге без GPU; разумный объём реализации до дедлайна.

Сосредоточься на действиях и последствиях, которые можно проверить на стенде. Различай опасность, неизвестное состояние и отсутствие маршрута. Синтетический показатель не выдавай за вероятность реального обрушения; расчётный маршрут — за подтверждённо безопасный путь в реальной шахте.

## Разделение работы

Предлагаемая зона Claude — интерфейс и пространственная визуализация в team/ui/. Зона Codex — симуляция, двойники, интеграция MQTT/Ditto, запуск и объединение изменений. Этот первый проход согласует экран и данные до параллельного написания связанных частей.

Работай в отдельной рабочей папке Git, открытой для этого задания. В первом проходе изменяй только team/ui/DESIGN.md; собственный программный интерфейс платформы и корневые документы пока не меняются. Общие изменения предложи в отчёте с обоснованием.

По завершении проверь git diff, создай локальный коммит только своего документа и сообщи его хеш, выводы и вопросы к контракту данных. Результат остаётся в рабочей ветке для проверки и объединения; публикация в GitHub в это задание не входит.

История чата Codex автоматически не передаётся. Общий контекст — перечисленные файлы и коммиты; не считай непроверенные утверждения другого помощника результатами испытаний.

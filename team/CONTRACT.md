## 2. Согласованное состояние для UI

Публикация shift последним не создаёт транзакцию между разными двойниками. Доставка через MQTT, обработка разными объектами Ditto и отдельные HTTP-чтения могут смешать поколения. Поэтому основной экран не собирает текущее состояние из независимых GET каждого объекта.

Симулятор по-прежнему создаёт и обновляет отдельные двойники выработок, работников, датчиков, участков, вариантов и журнала. Дополнительно он публикует их согласованную проекцию внутри shift одним modify /features через MQTT. Это данные платформы, а не обход Ditto.

У shift сохраняются признаки из DESIGN.md и добавляются:

| Признак | Тип value | Значение |
|---|---|---|
| contract_version | целое | 1; проверяется в каждом снимке |
| publication_seq | целое | монотонный номер публикации, включая heartbeat на паузе; сохраняется при reset и рестарте |
| pause_reason | строка | none или decision |
| scene | массив объектов | Согласованные состояния всех динамических дочерних объектов из mine.attributes.dynamic_ids; самого shift в массиве нет |

Элемент scene: {"thingId": "team040.mine:worker-01", "features": { ... }}. Признаки имеют обычную форму Ditto: {"properties":{"value":...,"unit":...}}. У каждого элемента scene те же tick, sim_time_s и idSimulationRun, что и у shift. Архивные run-двойники в scene не включаются: после завершения их результаты неизменны и читаются отдельно. Журнал и варианты входят в scene.

У mine.attributes добавляются:

- contract_version: 1.
- manifest: массив полных thingId статических и актуальных объектов, включая mine и shift, без архива run.
- dynamic_ids: массив полных thingId для элементов scene, без shift, mine и статических level.

Геометрия, nodes, связи и подписи остаются в атрибутах, как в DESIGN.md. Все эти поля задаёт один конфигурационный источник модели. UI не содержит отдельной схемы шахты и не считает маршруты.

Чтение:

1. GET /ditto/api/2/things/team040.mine:mine?fields=thingId,attributes.
2. GET /ditto/api/2/things?ids=...&fields=thingId,attributes пакетами до 20 ids из manifest.
3. Раз в секунду GET /ditto/api/2/things/team040.mine:shift?fields=thingId,features,_modified,_revision.
4. Для архива — GET по идентификаторам из shift.features.runs.properties.value, также пакетами до 20. Порядок ответа произвольный.

UI проверяет версию контракта и топологии, точное множество dynamic_ids (без дубликатов), одинаковые run/tick/sim_time_s вложенных состояний и целостность обязательных полей. При нарушении сохраняет последний полный снимок, показывает причину и блокирует команды. При смене топологии повторно читает атрибуты. Смена прогона не должна смешивать старые атрибуты или состояния с новыми.

Публикация зеркал отдельных двойников может отставать от проекции shift; это не скрывается в диагностике. Сквозной тест отдельно сверяет зеркала с одним поколением проекции после остановки модельного времени. UI при выборе объекта показывает согласованный снимок из scene, а отдельный endpoint объекта служит диагностике.

Цена решения — дублирование состояния в одном сообщении. Стенд должен измерить размер и задержку этой проекции; до этого не заявляем выдерживаемые частоты и лимиты. Полный JSON-снимок не экспортируется как россыпь метрик в InfluxDB.

## 3. Команды, повторы и неопределённый результат доставки

```text
POST /ditto/api/2/things/team040.mine:shift/inbox/messages/command?timeout=0
Content-Type: application/json
```

```json
{
  "command_id": "c-5f2a9c1e7b3d4a6098bc17e0f52a634d",
  "type": "condition.close_working",
  "target": "w-12",
  "run": "run-0003"
}
```

command_id: c- и 32 шестнадцатеричные цифры, созданные криптографическим генератором браузера. Повтор использует тот же идентификатор и то же тело. Симулятор читает Ditto-конверт из opentwins/live/messages/team040.mine/shift, проверяет topic, path и тело value. Список команд из DESIGN.md сохраняется; дополнительно вводится run.start_preset, target — id пресета из mine.attributes.presets.

Запись подтверждения хранит поля id, type, target, run, status, tick, sim_time_s, reason. tick и sim_time_s относятся к прогону из поля run. Для run.reset и run.start_preset запись содержит new_run. После смены прогона UI ищет подтверждение и в новом shift, не требует, чтобы run в записи совпал с новым idSimulationRun.

Последние 32 записи видны в shift.commands. Это окно отображения, не хранилище дедупликации. Сервис сохраняет журнал идентификаторов, тел команд и результатов на диске вместе с состоянием модели. Повтор известного идентификатора не выполняет действие второй раз, в том числе после reset/рестарта. Повтор с другим телом — command_id_conflict. Новый идентификатор с устаревшим run — invalid_run. Визуальное окно на 32 записи нельзя использовать для реализации этих гарантий.

HTTP 202 — «отправлена, не подтверждена». Применение — только по applied, отказ модели — по rejected. При сетевом тайм-ауте или HTTP 5xx UI пишет «Результат доставки неизвестен» и предлагает повтор с тем же command_id: ошибка могла произойти после передачи команды. Смена состояния не производится оптимистически.

Повтор уже достигнутого состояния с новым command_id считается applied без изменения модели, reason=already_in_state. Это не создаёт второй эффект сценария. Причины not_allowed_in_state, malformed, unknown_type, unknown_target и invalid_run остаются отказами. Для action.execute_option дополнительно передаётся decision_id из выбранного option; устаревшее решение отклоняется с stale_decision.

Прокси Codex слушает 127.0.0.1:8088, читает пароль из окружения на сервере и разрешает только GET API things для namespace team040.mine и точный POST выше с timeout=0. Он проверяет ids, методы, размер тела и Content-Type, не открывает произвольный Ditto API, удаляет клиентскую Authorization и не кеширует ответы. Статические файлы Claude размещаются в team/ui/public/.

## 4. Три вида времени и потеря связи

- Время измерения: measured_at_tick и measured_at_sim_s. Потерянный датчик не получает новое время измерения от того, что опубликован очередной heartbeat.
- Время модели: tick и sim_time_s. На паузе не растёт. data_quality и ограничения по измерениям считает модель.
- Поступление публикаций: publication_seq, _modified shift и HTTP Date. На паузе publication_seq продолжает расти. Настенные интервалы UI измеряет монотонным performance.now(), не вычитанием показаний часов браузера из времени сервера.

При первом HTTP-сбое UI сразу прекращает переходы положения и показывает ухудшение связи. Если за 2 секунды нет успешно прочитанного полного снимка, помечает экран как устаревший и блокирует команды; таймер работает и во время pending fetch. Через 3 неудачных опроса показывает «Платформа недоступна». Запрос имеет тайм-аут 3 секунды; параллельных опросов нет.

Успешное чтение старого состояния не делает его новым. Если publication_seq не меняется 5 секунд, UI показывает «Публикации модели остановились»; run_state=paused не является исключением, поскольку heartbeat должен работать. При первой загрузке начальный возраст оценивается по HTTP Date − _modified с учётом секундной точности; далее добавляется монотонно прошедшее время. Ответы без обязательных метаданных не выдают за актуальные.

Задержка истории не равна «не меньше 10 секунд»: flush_interval=10s задаёт период отправки накопленных метрик. До очередной отправки может оставаться меньше 10 секунд; сеть и обработка добавляют задержку. Фактическая задержка подлежит измерению. Оперативный UI не читает InfluxDB.

## 5. Инцидент, прогноз и сравнение

Инцидент открывается на переходе: проход open → closed; контролируемый участок получает danger; качество контролируемого участка переходит fresh → stale/lost. Инцидент объединяет одновременно действующие причины. Повтор того же условия не создаёт новую копию причины.

В первой версии при открытии инцидента модель сохраняет состояние принятия решения и приостанавливает модельное время: run_state=paused, pause_reason=decision. Команды и heartbeat продолжают обрабатываться. UI явно пишет «Модель на паузе для выбора действия». Изменение условия на паузе обновляет состояние решения и decision_id.

Варианты observe, stop_withdraw_zone и withdraw_all рассчитываются копиями одного состояния одним и тем же кодом переходов. Горизонт по умолчанию 900 модельных секунд — параметр демонстрации, не производственный норматив. Каждый option сообщает decision_id, comparison_key, forecast_tick, forecast_horizon_s и forecast_quality. action.execute_option применяет вариант к соответствующему состоянию и снимает паузу. action.withdraw_zone также считается решением и снимает паузу. Остановка участка сама по себе оставляет паузу: диспетчер может затем выбрать вывод или observe.

В прогнозе учитывается явно заданное расписание пресета. Надпись — «Прогноз модели на N секунд для заданного сценария», а не обещание реального исхода. Неполные данные маркируются partial, отсутствие ещё реализованного прогноза — «Прогноз не опубликован». Чисел-заглушек в боевом UI нет.

Пресет run.start_preset создаёт новый прогон из исходной конфигурации, применяет сценарное расписание (например, условие в модельную секунду 60), доходит до точки решения и приостанавливает модель. Сам пресет и его время берутся из mine.attributes.presets. Повтор пресета с теми же версиями, seed и состоянием даёт тот же comparison_key; выбор действия в ключ не входит.

comparison_key рассчитывает сервис из версии модели и параметров, топологии, seed, полного исходного состояния решения, будущего расписания условий, горизонта и состава сравниваемых людей. UI сравнивает только одинаковые ключи. Изменённое пользователем после решения условие делает прогон incomparable с первоначальным прогнозом; это явно записывается в результате.

run.reset завершает текущий прогон и начинает чистый. Прерванный reset прогон получает completion_reason=reset и не помечается как успешно завершённый вывод. Архив хранит прогноз отдельно от факта и не заменяет не полученный результат прогнозом.

Для run.reset принимается target="run" (интерфейс) или совместимый target="shift"
(служебные клиенты). Другие цели отклоняются. Повтор command_id не создаёт новый прогон.

## 6. Показатели без ложного успеха

| Признак (или суффикс у forecast_/actual_) | Определение |
|---|---|
| workers_in_danger / in_danger | Число людей в контролируемых зонах с актуальным hazard_state=danger в данный момент или на конце горизонта |
| danger_exposure_person_s | Интеграл числа таких людей по модельному времени; единица person*s |
| unknown_exposure_person_s | Отдельный интеграл для контролируемых зон с неизвестным состоянием; не считается нулевой опасностью |
| workers_no_route / no_route | Число оставшихся под землёй работников, для которых нет маршрута по правилам модели |
| workers_out / out | Число людей общей сравниваемой группы, достигших выхода |
| all_out | true только если вся общая группа достигла выхода |
| last_out_s | Длительность от решения до выхода всех людей общей группы; отсутствует, если all_out=false или горизонт исчерпан |
| downtime_s | Сумма секунд простоя по участкам, единица zone*s; в UI — «суммарный простой участков», не длительность всего прогона |

Для всех вариантов одной точки решения группа одна и та же: все люди, находившиеся под землёй в сохранённом состоянии. Поэтому вариант вывода одного участка не получает ложное «все вышли» относительно меньшей группы. Для отображения завершения приказа участка дополнительно существует withdrawal_state участка, отдельно от глобального all_out.

## 7. Правила маршрутов и неизвестности

- incident.scope_policy_version=2: при закрытии в scope входят домашние участки
  людей внутри закрытой выработки или людей, чей кратчайший путь в справочном
  графе с открытыми закрытыми выработками пересекает закрытие. Опасности и
  доступность выходов в справочном графе сохраняются; фактические пути по нему
  не исполняются. Неиспользуемая ветвь может дать пустой scope, общий путь —
  несколько участков. Участки с опасностью/потерей данных добавляются отдельно.
  scope_reasons содержит причины включения и работников для объяснения в UI.
- При обновлении старого checkpoint пересчитывается только ещё не выбранное
  активное решение: новый decision_id отклоняет устаревшую команду выбора.
  Уже исполняемый приказ, архив и ledger не переписываются. Версия правила и
  область входят в comparison_key; старые и новые результаты не приравниваются.

- Закрытые выработки и недоступные выходы исключаются из маршрутов. Выработка, закрывшаяся под работником, не переносит его на другой конец: человек останавливается на своей позиции, маршрут помечается none с причиной current_working_closed до отмены условия. Это упрощение модели, явно описываемое в данных и допущениях.
- В модели запрещается новый вход в danger или неизвестную контролируемую зону. Выход из текущего участка при наличии разрешённого пути обрабатывается отдельно от запрета входа; UI следует опубликованным ориентированным сегментам маршрута и не выводит это правило самостоятельно.
- Участок без датчиков по проекту не называется нормальным. Для проходов без датчиков используется отдельно документированное допущение модели о проходимости; UI подписывает «без датчиков, состояние не оценивается».
- При stale/lost hazard_state становится unknown, last_known_hazard_state и last_known_hazard_tick сохраняют последнюю оценку. Последний danger остаётся явно видимым. routing_restriction=blocked/allowed/unknown публикуется моделью отдельно; потеря датчика не снимает установленное ограничение.
- workers_unknown включает неизвестное положение, нерассчитанный маршрут или неизвестность контролируемого участка. Неизвестность фоновых проходов без датчиков показывается отдельно как допущение, а не прячется в норме.
- Отмена условия не возвращает работников и не запускает оборудование. action.resume_zone не телепортирует вышедших людей. При отсутствии требуемого персонала команда отклоняется с insufficient_workers; фактическая производительность остаётся нулевой. Возвращение после завершённого вывода в первой версии выполняется только новым прогоном.

## 8. Проверки перед объявлением интеграции рабочей

1. Команда проходит HTTP → live Ditto → MQTT → симулятор → MQTT → shift.commands; 202 не принимается за исполнение.
2. Повтор команды, конфликт тела с тем же id, повтор reset и рестарт не дублируют действие.
3. Native JSON scene/route/commands/events сохраняются в Ditto. Экспорт истории не создаёт точки по каждому элементу route и не падает на live-сообщениях. Для метрик заданы явные типы скаляров.
4. Один снимок shift согласован внутри себя даже при искусственно задержанных зеркалах двойников. UI отклоняет повреждённый снимок.
5. Heartbeat на паузе не вызывает ошибку зависания, потеря heartbeat при отвечающем Ditto — вызывает.
6. Измерены число сообщений, размер снимка, задержка команды и отображения, память и поведение при рестарте. До измерения указанная частота — цель.
7. Сценарий без маршрута не получает all_out=true и числовое время выхода всех. Reset сохраняет признак прерванного прогона.
8. В MQTT и браузерных ресурсах нет серверного Authorization; прокси не даёт доступа к произвольным namespace/методам.

### Правила и совместимость

ПДМ движется только по cycle_route, без нового входа в запрещённый участок и
без пересечения закрытого ребра. При паузе координаты неизменны. Отмена условия
не запускает машину: требуется resume_zone, работающие crew и оператор на борту.
Если ограничение появилось во время обратного рейса вне участка, машина
останавливается на текущем месте, а не телепортируется обратно в карман.

Люди перемещаются первыми. Машина сокращает свой шаг до max(0, gap−clearance),
но не задерживает/перенаправляет людей. Работники crew со status=working
исключены из встреч. Неподвижная машина не создаёт встреч; карман не блокирует
путь. Clearance — настройка синтетической модели, не гарантированный интервал
при произвольном появлении человека внутри него.

При stop/withdraw ПДМ едет в карман, с грузом сначала разгружается; закрытый
путь удерживает её на месте. **Уточнение общего пункта §7 предложения:** оператор
выходит и идёт пешком только при приказе вывода; при action.stop_zone без вывода
остаётся на борту, как требует таблица §3.6 задания. Availability не масштабирует
тонны окна. Возвращение людей после вывода не реализовано.

Журнал дополнен equipment.state_changed, equipment.hazard_changed,
equipment.conflict и model.migrated; поля и время — [event-journal.md](research/event-journal.md).
Обычные фазы цикла не создают событий, выход оператора — worker.state_changed.
Миграция 0.1 → 0.2 архивирует незавершённый прогон как reset, начинает новый,
сохраняет seq, ledger, подтверждения и архив с прежними лимитами. Старые результаты
не получают фиктивных LHD-метрик. Запись атомарна до публикации.

Визуальная интеграция и обновление UI-фикстур — отдельная работа Claude.
Геометрический hash для art-mode остаётся прежним. Максимальный переход при
текущих параметрах — 30 м за публикацию; это значение надо читать из реестра.
Измерения отдельного стенда, тесты и отклонения — [lhd-delivery.md](research/lhd-delivery.md).

# Интерфейс диспетчера смены

Экран диспетчера для условной подземной рудной шахты: пространственная схема, люди, участки, датчики, выходы, условия сценария, действия диспетчера, прогноз вариантов и архив прогонов. Реализация второго задания ([../CLAUDE_NEXT_TASK.md](../CLAUDE_NEXT_TASK.md)) по контракту [../CONTRACT.md](../CONTRACT.md); проект экрана — [DESIGN.md](DESIGN.md).

**Статус на 13 октября 2026 года: проверено только на тестовом сервере.** Платформа (Ditto, MQTT), прокси и симулятор при проверке не запускались. Всё, что ниже названо проверенным, проверено в headless Chrome 154 на Windows против `tools/mock_server.py`. Числа в фикстурах придуманы для тестов и не являются измерениями стенда.

## Состав

| Путь | Что это |
|---|---|
| `public/` | Боевая статика: `index.html`, CSS, ES-модули. Без сборки, фреймворка, CDN и сетевых шрифтов. Раздаётся по `/` |
| `tools/mock_server.py` | Тестовый HTTP-сервер на стандартной библиотеке Python. Воспроизводит записанные кадры; логики рудника в нём нет |
| `tools/build_fixtures.py` | Генератор контрактных фикстур |
| `fixtures/` | 23 сценария и их описание: [fixtures/README.md](fixtures/README.md) |
| `tools/cdp.py`, `tests/browser_support.py` | Драйвер headless Chrome по протоколу DevTools на стандартной библиотеке Python (Node.js и pip-пакеты не нужны) |
| `tests/` | Автоматические проверки (`unittest`), `screenshots.py` — снимки экрана и замеры |
| `test-output/` | Снимки и журналы прогонов; в git не попадает |

## Запуск на тестовом сервере

Из корня репозитория, нужен только Python 3:

```bash
python team/ui/tools/mock_server.py --port 8088 --scenario normal
```

Интерфейс — `http://127.0.0.1:8088/`. Страница выбора сценария и сбоев — `http://127.0.0.1:8088/__mock__/` (тестовый инструмент; боевой код к `/__mock__/` не обращается). Сценарии и их поведение описаны в [fixtures/README.md](fixtures/README.md).

Ссылки на виды: `#/scheme?sel=<thingId>&view=axo`, `#/scheme?view=plan&level=<id>`, `#/list?type=<kind>`, `#/runs`. Ссылка только открывает вид и выбирает объект; команды из URL не отправляются.

## Что получает интерфейс от платформы

Только запросы своего origin под `/ditto/`, ровно из разделов 2 и 3 контракта:

| Запрос | Когда |
|---|---|
| `GET /ditto/api/2/things/team040.mine:mine?fields=thingId,attributes` | при загрузке, при смене прогона или топологии |
| `GET /ditto/api/2/things?ids=…&fields=thingId,attributes` | пакетами до 20 идентификаторов из `manifest` |
| `GET /ditto/api/2/things/team040.mine:shift?fields=thingId,features,_modified,_revision` | раз в секунду, без параллельных опросов, тайм-аут 3 с |
| `GET /ditto/api/2/things?ids=…&fields=thingId,attributes,features` | архив прогонов из `shift.runs`, пакетами до 20 |
| `POST /ditto/api/2/things/team040.mine:shift/inbox/messages/command?timeout=0` | команда |

Интерфейс не считает маршруты, состояния опасности, прогнозы и счётчики, не содержит встроенной шахты и подставных чисел. Неопубликованное значение показывается как «—», неизвестный код — как неизвестный, никогда как норма. Строки платформы попадают в DOM только как текст.

Снимок `shift` принимается целиком или отклоняется (раздел 2 контракта): версия контракта и топологии, точное множество `dynamic_ids`, одинаковые прогон, тик и время модели во всех элементах `scene`, обязательные поля, заголовок `Date`, `_modified`, `_revision`. При нарушении на экране остаётся последний полный снимок с причиной, команды блокируются.

## Что проверено только на тестовом сервере

Всё. В частности, не проверены:

- ответы настоящего Ditto 3.3.7: заголовок `Date`, `_modified` и `_revision`, порядок и пропуски в ответе по `ids`, тела ошибок, 202 на `timeout=0`;
- прокси и его список разрешённых запросов;
- путь команды через live-сообщение и MQTT, время подтверждения;
- настоящий размер снимка `shift` и задержки;
- браузеры, кроме Chrome 154 на Windows; шрифты и отрисовка на Ubuntu судьи.

Состояния, которых нет ни в одной фикстуре (участок в `danger` прямо сейчас, качество `stale`, `egress_status = unknown`, выход `unavailable` или `unknown`, работник в опасной зоне, устаревшее положение), проверены подменой ответа сервера в коде теста; боевой код при этом не меняется. Команды `condition.instability_on/off` и `action.withdraw_zone` в фикстурах не разыграны: сервер отвечает на них причиной `not_scripted`, которой нет в контракте.

## Ограничения и известные недостатки

- На 1280×720 при нескольких отмеченных объектах подписи на схеме могут частично закрывать друг друга и контур соседнего участка.
- Появление или смена высоты баннера один раз перестраивает схему; метки при этом смещаются скачком до 18 px.
- На 1280×720 левая панель прокручивается: кнопка полного сброса и часть действий диспетчера находятся ниже первого экрана. Группа «Отправленные команды» ограничена 30 % высоты панели и прокручивается внутри.
- Число строк легенды на 1280×720 (сейчас четыре) зависит от ширины шрифта; на шрифтах Linux не проверено.
- При отклонённом снимке через 2 с строка состояния пишет «данные устарели», хотя HTTP отвечает; точную причину показывает баннер. Так следует из раздела 4 контракта.
- Перезагрузка страницы теряет список отправленных команд, включая идентификаторы для повтора; истиной остаётся состояние двойников.
- Защита от повторной отправки действует на пару «тип команды и цель». Два разных решения подряд (например, запуск варианта и вывод участка) интерфейс не запрещает; их должна отклонить модель.
- В плане горизонта выбор объекта с другого горизонта не переключает горизонт.
- Фикстуры занимают 10,6 МБ: каждый кадр хранит всю сцену, как её отдаёт `shift`.

## Отличия от DESIGN.md

- Архив прогонов — вкладка «Прогоны» в центральной области, а не вкладка рядом с журналом.
- Команды отдаются только из левой панели; в карточке объекта кнопок команд нет. Списки целей в левой панели следуют за выбранным объектом.
- Легенда на 1280×720 занимает до четырёх строк; пороги и второстепенные обозначения перенесены в сводку смены в карточке.
- При активном инциденте опубликованные маршруты работников его участка рисуются на схеме и без выбора объекта.
- Тексты и состояния следуют контракту там, где он уточняет проект: пауза модели для выбора действия, heartbeat `publication_seq`, «Результат доставки неизвестен», раздельные число людей и человеко-секунды.

## Предложения вне team/ui/ (зона Codex)

1. **Статика прокси** — каталог `team/ui/public/`, раздаётся по `/` с `Cache-Control: no-store`, файлы `.js` с типом `text/javascript`.
2. **Прокси пропускает `Date` без изменений и ничего не кеширует.** Причина: без разбираемого `Date`, `_modified` или `_revision` интерфейс отклоняет каждый снимок и блокирует команды.
3. **Чтение архива через прокси.** Причина: идентификаторы `team040.mine:run-NNNN` не входят в `manifest`, а запрос идёт с `fields=thingId,attributes,features`; проверка идентификаторов и полей в прокси должна это разрешать.
4. **Двоеточие и запятая в `ids`** отправляются без процентного кодирования, как записано в контракте. Причина: если прокси ждёт кодированный вид, чтение атрибутов не пройдёт.

## Вопросы и предложения к CONTRACT.md

Интерфейс в каждом пункте уже принимает один вариант (или оба); пункт нужен, чтобы симулятор и интерфейс не разошлись при первом совместном запуске.

| № | Вопрос или предложение | Причина |

| 1 | Закрепить список обязательных признаков. Сейчас снимок отклоняется, если нет любого из: у `shift` — `contract_version`, `publication_seq`, `tick`, `sim_time_s`, `idSimulationRun`, `run_state`, `pause_reason`, `speedup`, `seed`, `topology_version`, `conditions`, `workers_total/out/in_danger/no_route/unknown`, `commands`, `runs`, `scene`; у выработки — `passability`, `hazard_state`, `data_quality`; у участка — те же два и `work_state`, `withdrawal_state`; у датчика — `quality`, `link_state`, `measured_at_tick`; у работника — `status`, `egress_status` и, если он не `out` и не `unknown`, `at_working` и `offset_m`; у выхода, инцидента, варианта — `state`; у журнала — `last_seq`, `events` | Проверка работает на отказ: один пропущенный признак блокирует весь экран (причина видна в баннере).

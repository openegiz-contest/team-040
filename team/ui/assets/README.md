# Ассеты интерфейса диспетчера

## ПДМ — погрузочно-доставочная машина (LHD), класс 10 т

Трёхмерная модель подземной погрузочно-доставочной машины для сцены «Разрез массива»
в интерфейсе диспетчера. Узнаваемый низкий силуэт: шарнирно-сочленённая рама, ковш
впереди на стрелах, центральный шарнир сочленения, длинный задний силовой блок с
капотом, понижающимся назад, и противовесом, низкий боковой защитный навес (ROPS)
слева, где оператор сидит поперёк машины, четыре крупные шины с грунтозацепами,
сделанными геометрией, фары спереди, на навесе и сзади. Поза статичная, «на стоянке»:
ковш опущен и стоит ровно, рамы не повёрнуты.

**Это элемент оформления, а не часть модели рудника.** У ПДМ нет состояния в
симуляции: ни производственных показателей, ни координат из данных, ни движения.
Сцена ставит её в место, детерминированно выведенное из геометрии двойника, и
подписывает при наведении «ПДМ — элемент оформления, в модели нет её состояния».

### Происхождение

- Автор: Claude (Anthropic), 14 октября 2026 года.
- Основа сделана **скриптом на Python (`bpy`), запущенным из командной строки Blender 5.1**
  в фоновом режиме (`blender -b`): [`blender/lhd.py`](blender/lhd.py). Blender MCP на этом
  шаге не использовался.
- Затем **проход доработки выполнен через Blender MCP** в запущенном у пользователя
  Blender 5.1.2: инструмент `execute_blender_code` открыл `lhd.blend` и выполнил файл
  [`blender/lhd_mcp_pass.py`](blender/lhd_mcp_pass.py). Проход добавил диски колёс со
  ступицей и шестью гайками (`lhd_detail_rims`) и по одному гидрошлангу вдоль стрел с
  каждой стороны (`lhd_detail_hoses`), сохранил `lhd.blend` и заново экспортировал
  `lhd.glb`. Превью перерендерены через MCP тем же Cycles. Код прохода лежит в
  репозитории, поэтому модель пересобирается и без MCP (см. «Как пересобрать»).
- Источник истины — два скрипта, `lhd.py` и `lhd_mcp_pass.py`; `.blend`, `.glb` и
  превью — их продукты.
- Внешние модели, текстуры, HDRI и дополнения не использовались: вся геометрия
  строится кодом, материалы — Principled BSDF без изображений.
- Лицензия — лицензия репозитория (MIT, файл `LICENSE` в корне).

### Как пересобрать

Из корня репозитория:

```
"C:\Program Files\Blender Foundation\Blender 5.1\blender.exe" -b --factory-startup --python team/ui/assets/blender/lhd.py
"C:\Program Files\Blender Foundation\Blender 5.1\blender.exe" -b team/ui/assets/blender/lhd.blend --python team/ui/assets/blender/lhd_mcp_pass.py
```

Вторая команда повторяет проход доработки без MCP (он идемпотентен: сначала удаляет
свои объекты `lhd_detail_*`) и заново экспортирует `lhd.glb`. Превью она не рендерит,
а первая команда рендерит их до прохода. Превью в репозитории сняты после прохода,
в Blender через MCP.

Первый скрипт с нуля строит модель, экспортирует `lhd.glb`, считает треугольники по
самому экспортированному файлу (разбирает JSON и accessors glTF), проверяет бюджет
(при превышении завершается с кодом 1), рендерит превью и сохраняет `lhd.blend`.
Ручных шагов нет. Полная сборка — около 50 с (почти всё время — превью); с ключом
`-- --no-render` (только модель и экспорт) — около 1 с. Ключ `-- --samples N`
меняет число сэмплов превью.

### Бюджет и проверенные значения

| Требование | Факт |
|---|---|
| ≤ 8 000 треугольников | **7 960** треугольников после прохода доработки (6 912 после `lhd.py`) |
| ≤ 5 материалов | 5 |
| без текстур | 0 изображений, 0 текстур, UV не экспортируются |
| без Draco и расширений | `extensionsUsed` пуст: стандартный `GLTFLoader` three.js читает файл без декодеров |
| модификаторы применены | фаска (bevel) и взвешенные нормали (weighted normals) применены в скрипте, в файле — готовые нормали |
| масштаб | метры: длина 10,00 м, ширина 2,60 м, высота 2,30 м (по навесу), база 3,50 м, шины ⌀ 1,65 м |
| начало координат | на уровне земли под центром шарнира сочленения |
| оси glTF | вперёд = +X, вверх = +Y, левый борт (навес оператора) = −Z |

Иерархия: пустой узел `lhd` и дочерние меши без собственных трансформаций —
`lhd_body_front`, `lhd_body_rear`, `lhd_canopy`, `lhd_joint`, `lhd_lift_arms`,
`lhd_hydraulics`, `lhd_bucket`, `lhd_lamps`, `lhd_tyre_fl`, `lhd_tyre_fr`,
`lhd_tyre_rl`, `lhd_tyre_rr`; после прохода доработки также `lhd_detail_rims` и
`lhd_detail_hoses`.

### Материалы (направление «окрашенный металл», без сигнальных цветов)

| Материал | Цвет (sRGB) | Где |
|---|---|---|
| `lhd_paint_graphite` | `#3A4148`, шероховатость 0,55 | рамы, капот, навес, бак, ступицы колёс, корпуса фар |
| `lhd_steel_worn` | `#6E6A64`, шероховатость 0,62 | ковш, режущая кромка, износные полосы, штоки цилиндров, жалюзи, выхлоп, ступени, поручни |
| `lhd_rubber` | `#1C1D1F`, шероховатость 0,92 | шины, сиденье, задний буфер |
| `lhd_lens` | `#EFE6D6`, без свечения | стёкла фар (светит свет сцены, не материал) |
| `lhd_copper` | `#C8834F` | только две крышки пальца шарнира сочленения |

Металличность намеренно низкая (0–0,45): в three.js полностью металлический
материал без карты окружения выглядит почти чёрным. Медь на модели оставлена
минимальной, потому что в интерфейсе медь означает выбор. Жёлтого, красного и
оранжевого нет.
